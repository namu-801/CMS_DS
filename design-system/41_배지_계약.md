# Badge 계약 (Contract) — Tag · Status Badge · Status Text · Event Label · Count Badge

이 문서는 누르지 않고 **보여 주기만 하는** 작은 표시 다섯 가지의 사용 규칙입니다. 사람과 AI 모두 이 문서를 기준으로 쓰고 검사합니다.

- 기준일: 2026-10-27
- 근거: Figma `Badge · Component` 프레임, 코드 `src/components/Badge/`, 조사 `25_배지_조사.md`, 스펙 `26_배지_스펙안.md`(5~8절 결정), 대응표 `39_코드구현_대응표.md`
- 상태: Figma 완료(검사 통과), 코드 구현 완료(타입 검사·테스트 통과, 브라우저 확인)
- ⚑는 확정되지 않았거나 알려진 문제입니다. 10절에 모았습니다.

**핵심 원칙:** 뜻이 같으면 모양이 같습니다. 종류(`type`·`status`·`level`)를 고르면 색과 아이콘이 함께 정해지고, 색을 따로 칠하지 않습니다. 모두 누를 수 없는 표시입니다.

|---|---|---|
| `Tag` | 분류(GPS 그룹, 재생 시간, 반복 여부) | "GPS", "16:00:00 ~ 16:30:00", "반복재생" |

## 2. 속성과 넣을 수 있는 값

### 2-1. Figma Component property

| 컴포넌트 | 속성 | 타입 | 값 | 기본값 |
|---|---|---|---|---|
| `Tag` | `Type` | Variant | `GPS`, `Time`, `Repeat`, `RepeatOff` | `GPS` |
| | `Text` | Text | 글자 | `GPS` |
| `Status Badge` | `Status` | Variant | `Positive`(운행중), `Negative`(운행종료) | `Positive` |
| `Status Text` | `Status` | Variant | `Success`(성공), `Fail`(실패) | `Success` |
| `Event Label` | `Level` | Variant | `Danger`(위험), `Warning`(경고), `Caution`(주의) | `Danger` |
| `Count Badge` | `Text` | Text | "+N" | `+2` |

- `Status Badge`·`Status Text`·`Event Label`은 글자 속성이 없고 **종류마다 기본 글자**가 있습니다. 종류를 바꾸면 글자도 바뀝니다. 다른 글자가 필요하면 캔버스에서 글자를 바로 고칩니다.

### 2-2. 코드 Prop

```ts
<Tag type: "gps" | "time" | "repeat" | "repeat-off"; children: string />         // 글자 필수
<StatusBadge status: "positive" | "negative"; children?: string />            // 없으면 운행중·운행종료
<StatusText status: "success" | "fail"; children?: string />                  // 없으면 성공·실패
<EventLabel level: "danger" | "warning" | "caution"; children?: string />      // 없으면 위험·경고·주의
<CountBadge count: number />                                                   // 화면 "+N"
// 모두 className?(배치용)만 추가로 받음. style은 받지 않음
```

| Prop | 넣을 수 있는 값 | 그 밖의 값을 넣으면 |
|---|---|---|
| `type`·`status`·`level` | 위 목록만 | 컴파일 오류 |
| `children` | 글자(string)만 | 컴파일 오류 |
| `Tag` `children` | 필수 | 빠뜨리면 컴파일 오류 |
| `style` | 받지 않음 | 컴파일 오류 |

## 3. Figma 속성 ↔ 코드 Prop 대응표

| Figma | 코드 | 대응 | 값 대응 |
|---|---|---|---|
| `Tag` `Type` | `type` | 1:1 | `GPS`→`"gps"`, `Time`→`"time"`, `Repeat`→`"repeat"`, `RepeatOff`→`"repeat-off"` |
| `Tag` `Text` | `children` | 1:1(필수) | |
| `Status Badge` `Status` | `status` | 1:1 | `Positive`→`"positive"` … |
| `Status Text` `Status` | `status` | 1:1 | `Success`→`"success"` … |
| `Event Label` `Level` | `level` | 1:1 | `Danger`→`"danger"` … |
| 종류별 기본 글자(캔버스에서 고침) | `children?`(없으면 기본 글자) | 글자 → 선택 Prop | |
| `Count Badge` `Text` "+2" | `count={2}` | 글자 → 숫자 | 화면 "+2", 스크린리더 "외 2개" |

### 3-1. 일대일이 아닌 이유

1. **종류별 기본 글자:** Figma는 글자 속성을 없애고 Variant마다 글자를 두었습니다(종류를 바꾸면 글자가 같이 바뀌게, 2026-10-27 결정). 코드는 `children`을 안 주면 같은 기본 글자를 씁니다.
2. **`Count Badge`는 숫자를 받습니다.** "+"를 매번 쓰지 않게 하고, 스크린리더에는 "외 N개"로 읽히게 하려고 코드가 글자를 만듭니다.
3. **값 이름의 모양만 다릅니다.** Figma `RepeatOff` → 코드 `"repeat-off"`(코드 값은 소문자·하이픈 규칙).

## 5. 사용 규칙

1. 같은 뜻은 같은 모양입니다. GPS 태그의 진한 채움형은 쓰지 않습니다(2026-10-27 결정 B).
2. 색은 종류로만 정합니다. 배경·글자색을 덮어쓰지 않습니다.
3. 누르는 용도로 쓰지 않습니다(링크·버튼 아님). 누르는 칩이 필요하면 별도 컴포넌트로.
4. `Event Label`은 혼자 쓰지 않고, 옆에 무슨 이벤트인지 글자를 둡니다(색만으로 뜻을 전하지 않게).
5. `Status Text` 글자를 바꿨다면, 종류를 바꿀 때 글자도 함께 고칩니다(Figma 기본 동작상 직접 고친 글자는 남음).

## 6. 제대로 썼는지 확인하는 방법

### 6-1. Figma

- [ ] 이전 `tag`·`success/fail`·`car status`·위험 라벨 프레임이 아닌 새 컴포넌트입니다.
- [ ] 시간 태그에 "GPS" 같은 다른 종류의 기본 글자가 남아 있지 않습니다.
- [ ] 배경·글자 색을 덮어쓴 곳이 없습니다.

```js
const KEYS = ["f120c30dd02ba3b515041fd20951e698d471255d", "b4ca14b12fe8f1a3157d7603560414a3f0349042", "4abf271e850439c1c6a574df1f2586ab2fb06c37", "a0200809ea4d88c20a1d00d7715630d62a68f30b"];
const COUNT_KEY = "3d2c4c04ba6ae67ae9cc41338ca21bb1c521ff1c";
const OLD = new Set(["tag", "success/fail", "car status"]);
const problems = [], old = [];
for (const inst of figma.currentPage.findAllWithCriteria({ types: ["INSTANCE"] })) {
  const main = await inst.getMainComponentAsync(); if (!main) continue;
  const set = main.parent?.type === "COMPONENT_SET" ? main.parent : main;
  if (OLD.has(set.name.replace("\b", ""))) { old.push(inst.id); continue; }
  if (!KEYS.includes(set.key) && main.key !== COUNT_KEY) continue;
  for (const o of inst.overrides) { const bad = o.overriddenFields.filter(f => ["fills", "strokes"].includes(f)); if (bad.length) problems.push(`${inst.id}: 색 덮어쓰기`); }
}
return { problems, old };
```
