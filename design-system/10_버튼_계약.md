# Button 계약 (Contract)

이 문서는 디자인(Figma)과 코드가 함께 지켜야 하는 Button 사용 규칙입니다. 사람과 AI 모두 이 문서를 기준으로 버튼을 쓰고 검사합니다.

- 기준일: 2026-10-08 (Figma 세트와 코드를 다시 읽고 갱신)
- 근거: Figma `Button` 세트, 코드 `src/components/Button/`, 스펙 결정 `09_버튼_스펙안.md`, 토큰 `04_이름규칙.md`
- 상태: Figma 175개 Variant 완료, 코드 구현 완료(타입 검사·테스트 12개 통과)
- ⚑는 확정되지 않았거나 알려진 문제입니다. 9절에 모아 두었습니다.

## 2. 속성과 넣을 수 있는 값

### 2-1. Figma Component property

| 속성 | 타입 | 넣을 수 있는 값 | 기본값 |
|---|---|---|---|
| `Style` | Variant | `Primary`, `Secondary`, `Neutral`, `Outline`, `OutlineBrand`, `Plain`, `Destructive` | `Primary` |
| `Size` | Variant | `XSmall`, `Small`, `Medium`, `Large`, `XLarge` (⚑ 패널 표시 순서가 아직 `XSmall, Small, Large, Medium, XLarge`) | `Small` |
| `State` | Variant | `Default`, `Hover`, `Pressed`, `Disabled`, `Loading` | `Default` |
| `Label` | Text | 버튼 문구 | `추가` |
| `Icon Left` | Boolean | 켬 / 끔 | 끔 |
| `Icon Left Swap` | Instance swap | `Icon/*` 세트. 추천 8개: Plus, Right, Left, Delete, Edit, Refresh, Search, Loading | `Icon/Action/Plus` 20 |
| `Icon Right` | Boolean | 켬 / 끔 | 끔 |
| `Icon Right Swap` | Instance swap | 위와 같음 | `Icon/Arrow/Right` 20 |

### 2-2. 코드 Prop

```ts
type ButtonVariant = "primary" | "secondary" | "neutral" | "outline" | "outline-brand" | "plain" | "destructive";
type ButtonSize = "xsmall" | "small" | "medium" | "large" | "xlarge";
type IconName = keyof typeof icons; // 코드에 등록된 아이콘 32종(13_아이콘버튼_계약.md 2-2)

interface ButtonProps /* + 네이티브 <button> 속성(style, children, type, color 제외) */ {
  variant?: ButtonVariant;              // 기본 "primary"
  size?: ButtonSize;                    // 기본 "small"
  children: string;                     // 버튼 문구(필수, 글자만)
  iconLeft?: IconName;                  // 없으면 아이콘 없음
  iconRight?: IconName;
  loading?: boolean;                    // 기본 false. disabled보다 우선
  disabled?: boolean;                   // 기본 false
  fullWidth?: boolean;                  // 기본 false. 부모 너비를 채움
  type?: "button" | "submit" | "reset"; // 기본 "button"
  className?: string;                   // 배치(margin, grid 위치)용만
}
```

| Prop | 넣을 수 있는 값 | 기본값 | 그 밖의 값을 넣으면 |
|---|---|---|---|
| `variant` | 위 7개 | `"primary"` | 컴파일 오류 |
| `size` | 위 5개 | `"small"` | 컴파일 오류 |
| `children` | 글자(string) | 없음(필수) | 글자가 아니면 컴파일 오류 |
| `iconLeft`, `iconRight` | 코드에 등록된 아이콘 32종(목록은 `13_아이콘버튼_계약.md` 2-2) | 없음 | 컴파일 오류 |
| `loading`, `disabled`, `fullWidth` | `true` / `false` | `false` | — |
| `type` | `"button"`, `"submit"`, `"reset"` | `"button"` | 컴파일 오류 |
| `style` | 받지 않음 | — | 컴파일 오류 |
| 네이티브 속성 | `onClick`, `aria-*`, `name`, `form`, `id` 등 | — | 그대로 `<button>`에 전달 |

`ref`를 주면 실제 `<button>` 요소를 가리킵니다.

### 2-3. Style: 언제 쓰는지와 색 토큰

| Style | 언제 쓰는지 | Default 배경 | 테두리 | 글자·아이콘 |
|---|---|---|---|---|
| `Primary` | 화면이나 영역의 대표 동작(저장, 완료, 로그인) | `Surface/Brand/Strong` (Purple500) | 없음 | `Foreground/Neutral/Inverse` |
| `Secondary` | 남색 강조 동작(할당하기) | `Surface/Brand/Secondary` | 없음 | `Foreground/Neutral/Inverse` |
| `Neutral` | 대표 동작 옆의 보조 동작(취소) | `Surface/Neutral/Inverse` | 없음 | `Foreground/Neutral/Inverse` |
| `Outline` | 일반 동작(추가, 삭제, 수정, 미리보기) | `Surface/Neutral/Primary` | `Border/Neutral/Secondary` | `Foreground/Neutral/Secondary` |
| `OutlineBrand` | 보라 강조가 필요한 보조 동작(중복확인, 회원가입) | `Surface/Neutral/Primary` | `Border/Brand/Primary` | `Foreground/Brand/Primary` |
| `Plain` | 가장 약한 동작(이전, 다음) | 없음 | 없음 | `Foreground/Neutral/Quaternary` |
| `Destructive` | 삭제를 **최종 확인하는 모달 버튼**에만 | `Surface/Negative/Primary` | 없음 | `Foreground/Neutral/Inverse` |

### 2-4. State별 색 토큰

| State | 채움 Style(`Primary`, `Secondary`, `Neutral`, `Destructive`) | `Outline` | `OutlineBrand` | `Plain` |
|---|---|---|---|---|
| `Default` | 2-3 표 | 2-3 표 | 2-3 표 | 2-3 표 |
| `Hover` | 배경 `Interaction/Brand/PrimaryHover`(Purple600) · `…/SecondaryHover` · `Interaction/Neutral/InverseHover` · `Interaction/Negative/PrimaryHover` | 배경 `Interaction/Neutral/Fill` | 배경 `Interaction/Brand/SubtleHover` | 배경 `Interaction/Neutral/Fill` |
| `Pressed` | 배경 `…PrimaryPressed`(Purple700) · `…SecondaryPressed` · `…InversePressed` · `Interaction/Negative/PrimaryPressed` | 배경 `Interaction/Neutral/FillStrong`, 테두리 `Interaction/Neutral/ActiveBorder` | 배경 `Interaction/Brand/SubtlePressed` | 배경 `Interaction/Neutral/FillStrong`, 테두리 `Interaction/Neutral/ActiveBorder` |
| `Disabled` | 배경 `Surface/Neutral/Disabled`, 글자 `Foreground/Neutral/Inverse` | 배경 `Surface/Neutral/Secondary`, 테두리 `Border/Neutral/Secondary`, 글자 `Foreground/Neutral/Subtle` | 같음 | 배경 없음, 글자 `Foreground/Neutral/Subtle` |
| `Loading` | Default 색 + 왼쪽 아이콘 자리에 회전 아이콘 | 같음 | 같음 | 같음 |

### 2-5. Size별 토큰

| Size | 높이 | 글자 | 바깥 여백(아이콘 쪽) | 글자 쪽 여백 | 아이콘 | 아이콘–글자 간격 |
|---|---|---|---|---|---|---|
| `XSmall` | `Size/Height/ControlXSmall` 32 | `13/Medium` | `Spacing/Scale/8` | 12 | `Size/Icon/XSmall` 16 | 4 |
| `Small` (기본) | `Size/Height/ControlSmall` 40 | `15/SemiBold` | `Spacing/Scale/12` | 16 | `Size/Icon/Small` 20 | 4 |
| `Medium` | `Size/Height/ControlMedium` 48 | `18/SemiBold` | `Spacing/Scale/16` | 20 | `Size/Icon/Small` 20 | 6 |
| `Large` | `Size/Height/ControlLarge` 52 | `20/SemiBold` | `Spacing/Scale/20` | 24 | `Size/Icon/Medium` 24 | 8 |
| `XLarge` | `Size/Height/ControlXLarge` 56 | `20/SemiBold` | `Spacing/Scale/24` | 28 | `Size/Icon/Medium` 24 | 8 |

모든 크기에 공통으로 적용되는 값입니다.
- 모서리 `Radius/Scale/0`
- 테두리 두께 `Size/Border/Default`(1, 안쪽)
- 최소 너비 `Size/Hit/Small`(32)
- 너비는 내용에 맞춤(Hug)이 기본입니다.

**여백 구조**
- 글자 쪽 여백 = 바깥 여백 + 라벨 틀 좌우 여백 `Spacing/Scale/4`입니다. Figma `Label Wrap`, 코드 `.label`이 같은 구조입니다.
- 아이콘을 켜면 그쪽만 바깥 여백이 되어 4px 좁아집니다.
- 아이콘–글자 간격 = 버튼 간격(`Spacing/Scale/0`·`0`·`2`·`4`·`4`) + 4입니다.

## 3. Figma 속성 ↔ 코드 Prop 대응표

| Figma | 코드 | 대응 | 값 대응 |
|---|---|---|---|
| `Style` | `variant` | 1:1 | `Primary`→`"primary"`, `Secondary`→`"secondary"`, `Neutral`→`"neutral"`, `Outline`→`"outline"`, `OutlineBrand`→`"outline-brand"`, `Plain`→`"plain"`, `Destructive`→`"destructive"` |
| `Size` | `size` | 1:1 | `XSmall`→`"xsmall"`, `Small`→`"small"`, `Medium`→`"medium"`, `Large`→`"large"`, `XLarge`→`"xlarge"` |
| `Label` | `children` | 1:1 | 문구 그대로 |
| `Icon Left` + `Icon Left Swap` | `iconLeft` | 2:1 | 끔 → 넣지 않음, 켬 + `Icon/Action/Plus` → `"action_plus"` |
| `Icon Right` + `Icon Right Swap` | `iconRight` | 2:1 | 끔 → 넣지 않음, 켬 + `Icon/Arrow/Right` → `"arrow_right"` |
| `State=Default` | (없음) | 상태 → 없음 | 아무것도 안 주면 Default |
| `State=Hover` | CSS `:hover` | 상태 → 브라우저 | Prop 없음 |
| `State=Pressed` | CSS `:active` | 상태 → 브라우저 | Prop 없음 |
| `State=Disabled` | `disabled` | 상태 → Boolean | `disabled={true}` |
| `State=Loading` | `loading` | 상태 → Boolean | `loading={true}` |
| (없음) | CSS `:focus-visible` | 코드에만(Figma는 안내 프레임) | 2px `Border/Brand/Primary` 링, 2px 띄움. 모양은 Figma `Focus Ring · Guide` 프레임(node `173:15758`) |
| (없음) | `type`, `onClick` 등 | 코드에만 | 동작 정의 |
| 인스턴스 너비 Hug / Fill / Fixed | 기본 / `fullWidth` / 부모 레이아웃 | 레이아웃 | Fill → `fullWidth`, Fixed(예: 100) → 감싸는 레이아웃에서 너비 지정 |

**아이콘 이름 바꾸는 법**
- Figma 아이콘 Key(`action_plus_20`)에서 크기(`_20`)를 뺀 이름이 코드 이름입니다.
- 예: `Icon/Arrow/Right` → `arrow_right`, `Icon/Status/Loading` → `status_loading`

### 3-1. 일대일이 아닌 이유

1. **아이콘 속성 2개 → Prop 1개**
   - Figma는 Instance swap으로 아이콘을 "없음"으로 만들 수 없습니다. 그래서 켜고 끄는 Boolean과 무엇을 넣을지 고르는 Swap을 따로 둡니다.
   - 코드는 값이 있으면 보이고 없으면 안 보이는 Prop 하나로 충분합니다.
2. **아이콘 크기는 코드가 자동으로 고릅니다**
   - Figma는 Swap 속성 하나를 모든 Size가 같이 쓰기 때문에, 20px 아이콘을 `Size/Icon/*` 크기로 늘리거나 줄여 씁니다.
   - 코드는 버튼 크기에 맞는 그림을 직접 고릅니다: xsmall 16, small·medium 20, large·xlarge 24. 그 크기의 그림이 없으면 가장 가까운 그림을 크기 토큰에 맞춰 그립니다. 예: Search는 24만 있어서 small 버튼에서는 24 그림을 20으로 줄입니다.
   - 그래서 `iconLeft`에는 크기를 뺀 이름만 넣습니다.
3. **Hover·Pressed는 Prop이 아닙니다**
   - 사용자가 마우스를 올리거나 누를 때 브라우저가 정하는 상태라 코드에서 켜고 끌 이유가 없습니다.
   - Figma는 화면 설계서에 그 모양을 보여 주려고 Variant로 둡니다.
4. **Disabled·Loading은 Boolean입니다**
   - 화면 로직(입력이 덜 됐는지, 저장 중인지)이 정하는 상태입니다.
   - Figma에는 둘을 동시에 켠 조합이 없습니다. 코드에서는 `loading`이 우선이라 Loading 모양으로 보이고 클릭은 막힙니다.
5. **Loading은 native `disabled`를 쓰지 않습니다**
   - native `disabled`를 쓰면 키보드 포커스가 버튼에서 빠집니다.
   - 그래서 `aria-disabled`와 `aria-busy`를 붙이고 클릭(폼 제출 포함)을 코드에서 막습니다.
6. **Loading에서는 왼쪽 아이콘이 없습니다**
   - Figma와 코드 모두 왼쪽 아이콘 자리에 회전 아이콘이 들어갑니다. 오른쪽 아이콘은 그대로 둡니다.
7. **Focus는 코드에만 있습니다**
   - Figma Focus Variant는 이번에 만들지 않기로 했습니다.
   - 하지만 키보드 사용자를 위해 코드에는 반드시 포커스 표시가 있어야 합니다(8절).
8. **너비는 Prop 하나(`fullWidth`)만**
   - Figma는 너비를 인스턴스의 레이아웃 설정으로 정합니다.
   - 코드는 자주 쓰는 Fill만 Prop으로 두고, 고정 너비는 감싸는 레이아웃이 정합니다.
   - 버튼의 색·높이·여백을 바꾸는 통로(`style`)는 막아 두었습니다.

## 4. 1:1이 아니어도 괜찮은가

괜찮습니다. 위 8가지는 모두 **일부러 그렇게 만든 차이**이고, 시안과 화면이 달라지는 "값이 틀리는 실수"는 코드가 막습니다.

### 4-1. 코드가 자동으로 막는 것 (걱정하지 않아도 됨)

| 실수 | 어떻게 막는지 |
|---|---|
| Figma에 없는 Style·Size 값을 씀(`"danger"`, `"medium2"`) | 컴파일 오류(`npm run typecheck`) |
| 등록되지 않은 아이콘 이름 | 컴파일 오류 |
| `style`로 높이·색을 바꿈 | 컴파일 오류 |
| 문구 대신 다른 요소를 넣음 | 컴파일 오류 |
| 버튼 스타일에 원시 색·px 값이 들어감 | 테스트 실패(`npm test`) |
| 저장 중에 두 번 누르거나 폼이 두 번 제출됨 | `loading`이 클릭과 제출을 막음(테스트로 확인) |
| Hover·Pressed 모양을 코드에 고정해 버림 | 그런 Prop이 없어서 불가능 |

### 4-2. 사람이 신경 써야 하는 것 (절차로 관리)

| 지점 | 생길 수 있는 일 | 지키는 방법 |
|---|---|---|
| Figma에서 토큰 값을 바꿈 | 코드 색·크기가 옛 값으로 남음 | Figma Variable을 바꾸면 `tokens/figma-variables.json`을 다시 내보내고 `npm run tokens` 실행 |
| Figma에서 코드에 등록되지 않은 아이콘을 고름 | 개발자가 그 이름을 쓰면 컴파일 오류가 남(조용히 틀리지는 않음) | 그 아이콘을 Figma에서 내보내 `icons.generated.ts`에 추가 |
| 포커스 링이 Figma Variant에 없음 | 디자이너가 포커스 모양을 놓칠 수 있음 | 2026-10-09 규칙 확정. Variant 대신 Figma `Focus Ring · Guide` 프레임(node `173:15758`)에 예시를 둠 |
| 고정 너비 버튼에 긴 문구 | Figma·코드 모두 글자가 넘침 | 문구 길이에 맞는 너비 또는 Hug |
| Figma에 `State=Hover` 인스턴스를 화면 시안에 둠 | 개발자가 어떤 상태가 기본인지 헷갈림 | 화면 시안은 `Default`·`Disabled`만, 나머지는 상호작용 설명용 프레임에만 |
| 아이콘 크기 처리 차이 | Figma(늘리고 줄임)와 코드(크기별 그림)의 선 두께가 0.1~0.4px 차이 | 허용 범위로 둠 |

요약하면, **값이 틀리는 문제는 타입과 테스트가 자동으로 잡고, 남는 것은 "Figma를 바꾸면 코드도 다시 맞춘다"는 동기화 절차**입니다. 그래서 7절의 동기화 절차가 중요합니다.

## 5. 사용 규칙

1. 한 영역(모달 하단, 폼 하단 등)에 `Primary`는 하나만 둡니다. 나머지는 `Neutral`, `Outline`, `Plain`을 씁니다.
2. `Destructive`는 삭제를 최종 확인하는 모달 버튼에만 씁니다. 목록 위의 "삭제" 버튼은 `Outline` + 왼쪽 아이콘입니다.
3. `XLarge`는 로그인·회원가입처럼 화면의 대표 동작에 씁니다. 모든 Style에 있지만, 일반 화면에서는 `Small`~`Large`를 씁니다.
4. 아이콘만 있는 버튼은 `Button`이 아니라 `IconButton`(`13_아이콘버튼_계약.md`)을 씁니다. 문구를 비우지 않습니다.
5. 문구는 동사로, 짧게 씁니다(예: 저장, 추가, 할당하기). 문구 끝에 마침표를 붙이지 않습니다.
6. 아이콘 색은 버튼이 정합니다. 아이콘 색을 따로 바꾸지 않습니다.
7. 폼 제출 버튼은 `type="submit"`을 명시합니다. 나머지는 기본값(`"button"`) 그대로 둡니다.

## 6. 제대로 썼는지 확인하는 방법

### 6-1. Figma

**눈으로 확인**
- [ ] 레이어 패널에서 버튼이 컴포넌트 인스턴스(◇)이고, 메인 컴포넌트가 `Button`입니다.
- [ ] 오른쪽 패널에서 `Style`, `Size`, `State`, `Label`, `Icon …` 외에 바꾼 값이 없습니다. 인스턴스 메뉴의 "Reset all changes"를 눌러도 모양이 바뀌지 않아야 합니다(문구·아이콘 제외).
- [ ] 화면 시안에서는 `State=Default` 또는 `Disabled`를 씁니다.
- [ ] 고른 아이콘이 코드에 등록된 32종 안에 있습니다. 없으면 개발 전에 추가를 요청합니다.

**스크립트로 확인(Figma 플러그인 API)**

인스턴스마다 메인 컴포넌트가 `Button` 세트인지, 허용된 것 외에 덮어쓴 값이 없는지 검사합니다.

```js
const BUTTON_SET_KEY = "6955c82b89936b8fa41ab135e5546c0c389ba864";
// 허용: 문구, 아이콘 켜기/끄기, 아이콘 교체, 인스턴스 너비(Fill/Fixed)
const ALLOWED = new Set(["characters", "visible", "mainComponent", "width", "layoutGrow", "layoutAlign", "primaryAxisSizingMode", "layoutSizingHorizontal"]);
const problems = [];
for (const inst of figma.currentPage.findAllWithCriteria({ types: ["INSTANCE"] })) {
  const main = await inst.getMainComponentAsync();
  if (main?.parent?.type !== "COMPONENT_SET" || main.parent.key !== BUTTON_SET_KEY) continue;
  for (const o of inst.overrides) {
    const bad = o.overriddenFields.filter(f => !ALLOWED.has(f));
    if (bad.length) problems.push(`${inst.name} (${inst.id}): ${bad.join(", ")}`);
  }
}
// 분리(Detach)된 옛 버튼 찾기: 이름이 btn-로 시작하거나 Button인 일반 프레임
const detached = figma.currentPage.findAll(n => n.type === "FRAME" && /^(btn-|Button$)/.test(n.name));
return { problems, detached: detached.map(n => n.id) };
```

### 6-2. 코드

**자동 검사(저장소 루트에서 실행)**

| 명령 | 확인하는 것 |
|---|---|

**찾아보기(화면 코드를 만든 뒤 주기적으로)**

## 8. 예시

### 8-1. 정상 사용

**Figma**
- 모달 하단: `Neutral / Small / Default` "취소" + `Primary / Small / Default` "저장"
- 목록 상단: `Outline / Small / Default` "추가" + `Icon Left` 켬, Swap `Icon/Action/Plus`
- 할당: `Secondary / Small / Default` "할당하기" + `Icon Right` 켬, Swap `Icon/Arrow/Right`
- 로그인: `Primary / XLarge / Default` "로그인", 인스턴스 너비 Fill
- 삭제 확인 모달: `Neutral` "취소" + `Destructive` "삭제"

**코드**

```tsx
import { Button } from "@/components/Button";

<Button variant="neutral" onClick={close}>취소</Button>
<Button type="submit" loading={isSaving}>저장</Button>

<Button variant="outline" iconLeft="action_plus" onClick={addRow}>추가</Button>
<Button variant="secondary" iconRight="arrow_right" onClick={assign}>할당하기</Button>

<Button size="xlarge" fullWidth type="submit">로그인</Button>
<Button variant="destructive" onClick={confirmDelete}>삭제</Button>
<Button disabled={!isValid}>다음</Button>
```

### 8-2. 시스템을 우회하는 반례

| 반례 | 왜 문제인지 | 바르게 |
|---|---|---|
| Figma: 인스턴스를 Detach한 뒤 배경을 `#7778FD`로 칠함 | 토큰 연결이 끊겨 색이 바뀌어도 따라가지 않음 | `Button` 인스턴스 그대로 사용 |
| Figma: `Primary` 인스턴스의 배경을 빨강으로 덮어씀 | 위험 동작인데 hover·pressed 색이 보라로 남음. 검사 스크립트에 `fills`로 걸림 | `Style=Destructive` |
| Figma: 높이를 42로 직접 바꿈 | 크기 단계 밖. 글자·여백·아이콘이 크기와 안 맞음 | `Size=Small`(40) |
| Figma: `Label`을 비우고 아이콘만 켬 | 버튼 이름이 없음(접근성) | `IconButton` |
| Figma: 아이콘 색을 따로 바꿈 | 상태가 바뀔 때 글자색과 어긋남 | 버튼이 정하는 색 그대로 |
| 코드: `<button className="bg-[#7778FD] h-[42px] px-6">저장</button>` | 원시 값, 시스템 밖 버튼 | `<Button>저장</Button>` |
| 코드: `<Button className="bg-red-500">삭제</Button>` | 색 덮어쓰기. hover·focus 색이 안 맞음 | `<Button variant="destructive">` |
| 코드: `<Button style={{ height: 42 }}>` | 컴파일 오류. 크기 단계 밖 | `size="small"` |
| 코드: `<Button variant="danger">` | 컴파일 오류. Figma에 없는 값 | `variant="destructive"` |
| 코드: `<div onClick={save}>저장</div>` | 키보드로 못 누르고, 스크린리더가 버튼으로 못 읽음 | `<Button onClick={save}>` |
| 코드: 저장 중에 문구만 "저장 중…"으로 바꾸고 클릭은 그대로 둠 | 중복 제출 | `loading={isSaving}` |
| 코드: 비활성을 `className="opacity-50 pointer-events-none"`으로 흉내 | 키보드·스크린리더에는 여전히 누를 수 있는 버튼 | `disabled` |
| 코드: 한 모달 하단에 `variant="primary"` 두 개 | 대표 동작이 불분명 | 하나는 `neutral` 또는 `outline` |

## 9. 접근성 요구사항

### 9-1. 필수 (지금 코드가 지키는 것 포함)

| 항목 | 요구사항 | 지금 코드 | 근거 |
|---|---|---|---|
| 요소 | 네이티브 `<button>`. 기본 `type="button"` | 적용 | WCAG 4.1.2 |
| 이름 | 보이는 문구가 버튼 이름. 문구 없는 버튼 금지(아이콘만 있으면 `IconButton` + `aria-label`) | `children` 필수(글자만) | WCAG 2.5.3, 4.1.2 |
| 아이콘 | 장식용 `aria-hidden="true"`, 포커스 받지 않음 | 적용 | WCAG 1.1.1 |
| 키보드 | Tab으로 이동, Enter·Space로 실행 | 네이티브 `<button>` 기본 동작 | WCAG 2.1.1 |
| 포커스 표시 | `:focus-visible`일 때 포커스 링이 보여야 함 | 2px `Border/Brand/Primary`, 2px 띄움(2026-10-09 확정). 링 대비: 흰 배경 3.57, `Neutral100` 3.27, `Navy0` 3.26, `Navy100` 3.04, `Navy900` 4.70 — 모두 3:1 이상 | WCAG 2.4.7, 1.4.11 |
| 비활성 | native `disabled`(포커스 순서에서 빠짐). 이유를 알려야 하면 근처에 안내 문구 | 적용 | WCAG 4.1.2 |
| 로딩 | `aria-busy="true"`, `aria-disabled="true"`, 클릭·제출 차단, 포커스 유지, 문구 유지. 결과는 화면의 알림 영역(`aria-live`)으로 알림 | 버튼 쪽 적용. 알림 영역은 화면에서 구현 | WCAG 4.1.3 |
| 클릭 영역 | 최소 32×32(`Size/Hit/Small`) | 모든 Size 높이 32 이상, 최소 너비 32 | WCAG 2.5.8(최소 24) |
| 움직임 | 움직임 줄이기 설정이면 회전을 멈춤 | `prefers-reduced-motion`에서 회전 없음 | WCAG 2.3.3 |
| 고대비 모드 | Windows 고대비 모드에서도 버튼 테두리가 보임 | `forced-colors`에서 시스템 테두리 | WCAG 1.4.11 |

### 9-2. 색 대비 (글자 vs 배경)

일반 글자는 4.5:1 이상이어야 합니다. 큰 글자(24px 이상, 또는 굵은 18.66px 이상)는 3:1 이상입니다. 비활성 버튼은 대비 기준에서 제외됩니다.

| Style | Default | Hover | Pressed |
|---|---|---|---|
| `Primary` | 4.83 | 6.95 | 9.90 |
| `Secondary` | 16.75 | 12.44 | 8.57 |
| `Neutral` | 9.00 | 13.77 | 18.88 |
| `Outline` | 13.77 | 10.93 | 9.48 |
| `OutlineBrand` | 4.83 | **4.39** ⚑ | **3.91** ⚑ |
| `Plain` | 4.54 | **3.61** ⚑ | **3.13** ⚑ |
| `Destructive` | **4.19** ⚑ | 5.93 | 8.38 |

**굵게 표시한 값은 일반 글자 기준(4.5)에 못 미칩니다.**
- 큰 글자 기준(3:1)으로는 모두 통과합니다. `Large`·`XLarge`(20/SemiBold)는 SemiBold를 굵은 글자로 볼지에 따라 판정이 달라집니다.
- `Primary`는 2026-10-08에 한 단계씩 진하게 바꿔(Default Purple500, Hover Purple600, Pressed Purple700) 모두 통과합니다. 이전 Default(`#7778FD`)는 3.57이었습니다.
- `Surface/Brand/Primary`(Purple400)는 탭·페이지 번호 등 다른 곳에서 그대로 씁니다. 그곳에 흰 글자를 올리면 같은 대비 문제가 있으니, 해당 컴포넌트를 만들 때 함께 검토합니다.
- 테두리는 글자로 버튼임을 알 수 있어서 대비 기준(1.4.11) 대상이 아닙니다. 참고로 `Outline` 테두리 1.45, `OutlineBrand` 테두리 3.57입니다.
