# Checkbox 계약 (Contract)

이 문서는 디자인(Figma)과 코드가 함께 지켜야 하는 Checkbox(항목 하나를 켜고 끄기) 사용 규칙입니다. 사람과 AI 모두 이 문서를 기준으로 쓰고 검사합니다.

- 기준일: 2026-10-20
- 근거: Figma `Checkbox` 세트, 코드 `src/components/Checkbox/`, 조사 `20_체크박스_조사.md`, 스펙 결정 `21_체크박스_스펙안.md`, 토큰 `04_이름규칙.md`
- 상태: Figma 6개 Variant 완료, 코드 구현 완료(타입 검사·테스트 통과, 브라우저에서 상태·키보드 확인)
- 여러 선택지 중 **하나만** 고르는 것은 Radio(`19_라디오_계약.md`)를 씁니다.
- ⚑는 확정되지 않았거나 알려진 문제입니다. 10절에 모아 두었습니다.

**핵심 원칙:** 체크박스는 **하나씩 따로** 켜고 끕니다. 켜짐/꺼짐은 같은 컴포넌트의 상태이며, 켜졌다고 다른 컴포넌트로 바꾸지 않습니다. 화면에 글자를 숨겨도 이름(글자)은 남깁니다.

### 2-2. 코드 Prop

```ts
interface CheckboxProps {
  label: ReactNode;                         // 필수. 항목 글자 = 이름. 일부만 굵은 글도 가능
  hideLabel?: boolean;                      // 기본 false. 화면에서만 숨김, 클릭 영역 32
  checked?: boolean;                        // 켜짐 여부(제어 방식)
  defaultChecked?: boolean;                 // 처음 켜짐 여부(내부에서 관리). 기본 false
  onCheckedChange?: (checked: boolean) => void;
  disabled?: boolean;                       // 기본 false. 켜짐 여부와 함께 쓸 수 있음
  message?: string;                         // 아래 오류 문구. 주면 aria-invalid
  className?: string;                       // 배치용만
  // 그 밖에 name, value, id, required, onBlur 등 네이티브 input 속성은 그대로 전달. ref는 input으로
}
```

| Prop | 넣을 수 있는 값 | 기본값 | 그 밖의 값을 넣으면 |
|---|---|---|---|
| `label` | 글자, 또는 일부만 `<strong>`인 글 | 없음(필수) | 빠뜨리면 컴파일 오류 |
| `checked`, `defaultChecked` | `true` / `false` | 비제어, `false` | `"mixed"` 등은 컴파일 오류(혼합 상태 없음) |
| `hideLabel`, `disabled` | `true` / `false` | `false` | — |
| `message` | 글자만 | 없음 | 글자가 아닌 것(`<b>…</b>` 등)은 컴파일 오류 |
| `size`, `style`, `type` | 받지 않음 | — | 컴파일 오류 |
| `onChange`, `aria-invalid`, `aria-describedby` | 받지 않음 | — | 컴파일 오류(`onCheckedChange`·`message`가 대신 맡음) |

## 3. Figma 속성 ↔ 코드 Prop 대응표

| Figma | 코드 | 대응 | 값 대응 |
|---|---|---|---|
| `Checked=Off` / `On` | `checked`(제어) 또는 `defaultChecked`(비제어) + `onCheckedChange` | 상태 → Boolean | `Off` → `false`, `On` → `true` |
| `State=Default` | (없음) | 상태 → 없음 | 아무것도 안 주면 Default |
| `State=Hover` | CSS `:hover` | 상태 → 브라우저 | Prop 없음 |
| `State=Disabled` | `disabled` | 1:1 | `Checked`와 함께 → `disabled` + `checked`/`defaultChecked` |
| `Label` | `hideLabel` | 뜻이 반대 | `Label` 켬 → `hideLabel` 안 줌, 끔 → `hideLabel` |
| `Label Text` | `label` | 1:1(코드는 필수, 일부만 굵은 글도 가능) | `이메일 기억하기` → `label="이메일 기억하기"` |
| `Message` + `Message Text` | `message` | 둘 → 하나 | `Message` 켬 + `약관에 동의해 주세요.` → `message="약관에 동의해 주세요."`, 끔 → `message` 안 줌 |
| (없음) | `name`, `value`, `id`, `required`, `ref` | 코드에만 | 폼 제출·연결 |
| (없음) | 포커스 링, 글자 끈 체크박스의 클릭 영역 32 | 코드에만 | |

### 3-1. 일대일이 아닌 이유

1. **켜짐은 사용자가 바꾸는 값입니다.** Figma는 화면 설계서에 두 모양을 보여 주려고 `Checked`를 Variant로 둡니다. 코드에서는 누르면 바뀌어야 하므로 값(`checked`)과 바뀔 때 알림(`onCheckedChange`)으로 나눕니다. 바깥에서 값을 들고 있을 때(약관 동의 검사 등)는 `checked`, 체크박스가 알아서 들고 있어도 될 때는 `defaultChecked`를 씁니다.
2. **Hover는 Prop이 아닙니다.** 브라우저가 정하는 상태입니다(Button·TextField·Radio와 같음).
3. **글자는 코드에서 항상 필요합니다.** 글자를 숨긴 체크박스도 스크린리더가 무엇을 켜는지 읽어야 합니다. 그래서 `label`은 필수이고 숨길 때만 `hideLabel`을 씁니다. Figma `Label`과 `hideLabel`은 뜻이 반대입니다(TextField·Radio와 같은 방식).
4. **`label`은 글자만이 아니라 일부만 굵은 글도 받습니다.** Figma `Label Text` 속성은 한 가지 글꼴만 담을 수 있어서, 약관 동의처럼 일부만 굵게 쓰는 글은 Figma에서 `Label`을 끄고 화면에 글자를 따로 놓습니다. 코드에서는 따로 놓으면 글자를 눌러도 켜지지 않고 이름도 연결되지 않으므로, 굵은 부분이 섞인 글을 `label`에 그대로 넣습니다.
5. **`Message` 두 속성은 코드에서 하나입니다.** Figma는 켜고 끄기(Boolean)와 글자(Text)를 따로 둬야 하지만, 코드는 문구가 있으면 보여 주고 없으면 숨기면 됩니다. 문구가 있으면 오류 상태(`aria-invalid`)도 함께 켜집니다. 그래서 문구 없이 오류만 켜거나, 오류가 아닌 안내 문구를 넣는 것은 할 수 없습니다.
6. **`onChange` 대신 `onCheckedChange`입니다.** 화면 코드가 이벤트에서 값을 꺼내는 대신 켜짐 여부(`true`/`false`)를 바로 받습니다. 비활성일 때 바뀌지 않도록 막는 일도 컴포넌트가 맡습니다.
7. **포커스 링과 클릭 영역 32는 코드에만 있습니다.** 키보드 사용자와 작은 상자의 누르기 편의를 위한 것이고, 화면 모양은 Figma와 같습니다.

## 4. 시안 쓰임별 정답 조합

새 화면도 이 표의 조합을 그대로 씁니다. 표에 없는 쓰임이 생기면 가장 가까운 줄을 따르고, 스펙 문서에 줄을 추가합니다.

| 쓰임 | Figma | 코드 |
|---|---|---|
| 로그인 "이메일 기억하기" | `Label` 켬, `Label Text` `이메일 기억하기`. 켜짐도 같은 `Checkbox`의 `Checked=On`(다른 컴포넌트로 바꾸지 않음) | `<Checkbox label="이메일 기억하기" checked={remember} onCheckedChange={setRemember} />` |
| 회원가입 약관 동의(일부만 굵은 글) | `Label` 끔 + 오른쪽에 화면 글자를 간격 8로 배치. 동의 안 하고 "가입"을 누른 화면은 `Message` 켬, `약관에 동의해 주세요.` | `<Checkbox label={<>가입 시 <strong>이용약관</strong> …</>} checked={agree} onCheckedChange={setAgree} message={submitted && !agree ? "약관에 동의해 주세요." : undefined} />` |
| 표·목록 행 선택(앞으로) | `Label` 끔, `Label Text`에 그 행의 이름 | `<Checkbox label={행 이름} hideLabel />` |

## 5. 사용 규칙

1. 체크박스는 항목 하나를 켜고 끌 때 씁니다. 여러 선택지 중 하나만 고르면 Radio를 씁니다.
2. 켜짐은 같은 `Checkbox`의 `Checked=On`으로 나타냅니다. 이전처럼 켜짐 전용 컴포넌트로 바꾸지 않습니다.
3. 항목 글자는 "무엇을 켜는지"가 드러나게 씁니다(예: "이메일 기억하기"). 너비는 글자에 맞춰 자동이며 인스턴스 너비를 직접 줄이지 않습니다.
4. 글자를 끈 체크박스(표 행, 약관 동의)도 `Label Text`에 그 항목을 가리키는 글자를 적습니다. 코드에서 이 글자가 이름이 됩니다.
5. 일부만 굵은 글은 Figma에서는 `Label`을 끄고 화면에 따로 놓고, 코드에서는 `label`에 넣습니다. 어디를 굵게 할지는 화면이 정합니다.
6. 폼 버튼은 항상 누를 수 있게 둡니다. 꼭 켜야 하는 체크박스를 켜지 않고 누르면 그 체크박스 아래에 오류 문구를 보여 줍니다(로그인 화면과 같은 규칙, 2026-10-17).
7. 오류 문구는 한 줄로 짧게 씁니다(예: "약관에 동의해 주세요."). 문구가 길면 체크박스 전체가 넓어집니다.
8. 화면 시안에는 `Default`와 `Disabled`를 씁니다. `Hover`는 상호작용 설명용 프레임에만 씁니다.
9. 상자·체크·글자 색을 직접 바꾸지 않습니다. 선택된 행의 배경색 등은 표·목록이 정합니다.

### 6-1. Figma

**눈으로 확인**
- [ ] 레이어 패널에서 체크박스가 `Checkbox` 인스턴스(◇)입니다. 이전 `btn-check`, `checkbox`, `Checkbox_on_text`가 아닙니다.

```js
    continue;
  }
  if (main?.parent?.type !== "COMPONENT_SET" || main.parent.key !== CHECKBOX_SET_KEY) continue;
  for (const o of inst.overrides) {
    const bad = o.overriddenFields.filter(f => !ALLOWED.has(f));
    if (bad.length) problems.push(`${inst.name} (${inst.id}): ${bad.join(", ")}`);
  }
  const p = inst.componentProperties;
  const val = (prefix) => p[Object.keys(p).find(k => k.startsWith(prefix))].value;
  if (val("Label Text#") === "선택 항목") defaultText.push(`${inst.id}: 이름을 안 적음`);
  if (val("Message#") === true && val("Message Text#") === "오류 문구") defaultText.push(`${inst.id}: 오류 문구 기본값`);
}
return { problems, defaultText, oldOnes };
```

## 7. 예시

### 7-1. 정상 사용

**Figma**
- 로그인 "이메일 기억하기": `Checkbox` `Label Text` `이메일 기억하기`. 입력 전 화면 `Off / Default`, 입력 중 화면 `On / Default`(같은 컴포넌트)
- 회원가입 약관 동의: `Checkbox` `Label` 끔 + 오른쪽 화면 글자 "가입 시 **이용약관** 및 **개인정보처리방침**에 동의합니다."(간격 8). 동의 안 하고 누른 화면은 `Message` 켬, `약관에 동의해 주세요.`

**코드**

```tsx
import { Checkbox } from "@/components/Checkbox";

// 체크박스가 알아서 값을 들고 있음
<Checkbox label="이메일 기억하기" name="remember" defaultChecked />

// 바깥에서 값을 들고 검사: 버튼은 항상 활성, 동의 안 하고 누르면 오류 문구
const [agree, setAgree] = useState(false);
const [submitted, setSubmitted] = useState(false);

<Checkbox
  label={<>가입 시 <strong>이용약관</strong> 및 <strong>개인정보처리방침</strong>에 동의합니다.</>}
  checked={agree}
  onCheckedChange={setAgree}
  message={submitted && !agree ? "약관에 동의해 주세요." : undefined}
/>
<Button onClick={() => setSubmitted(true)}>가입</Button>

// 표 행 선택: 화면에 글자는 없지만 이름은 행 내용으로
<Checkbox label={`${row.name} 선택`} hideLabel checked={selected.has(row.id)} onCheckedChange={(on) => toggle(row.id, on)} />

// 켜진 채로 바꿀 수 없음
<Checkbox label="시스템 공지 받기" defaultChecked disabled />
```

### 7-2. 시스템을 우회하는 반례

| 반례 | 왜 문제인지 | 바르게 |
|---|---|---|
| Figma: 이전 `btn-check`·`checkbox`를 그대로 씀 | 토큰이 연결돼 있지 않고 꺼짐 테두리 대비가 2.52로 부족함 | `Checkbox` |
| Figma: 켜짐 화면에서 `Checkbox_on_text`로 바꿔 놓음 | 켜면 글자 굵기까지 달라지고, 개발자가 다른 컴포넌트로 오해 | 같은 `Checkbox`의 `Checked=On` |
| Figma: 상자 색을 직접 칠해 켜짐·오류처럼 보이게 함 | 토큰이 끊기고 상태와 맞지 않음 | `Checked` 속성으로. 오류는 `Message`로 |
| Figma: 글자 끈 체크박스의 `Label Text`를 "선택 항목"으로 둠 | 개발자·AI가 이름을 알 수 없음 | 항목 이름을 적음 |
| Figma: 오류 문구를 화면에 글자로 따로 놓음 | 위치·색이 체크박스마다 달라짐 | `Message` 켜고 `Message Text` |
| 코드: `<input type="checkbox" />`를 직접 씀 | 모양·포커스·이름·오류 연결이 없음 | `<Checkbox>` |
| 코드: `<Checkbox label="" hideLabel /><span>약관 동의</span>` | 글자를 눌러도 안 켜지고 스크린리더가 이름을 모름 | 글자를 `label`에 넣음 |
| 코드: 동의 전에 "가입" 버튼을 `disabled` | 왜 못 누르는지 알 수 없음. 서비스 폼 규칙과 다름 | 버튼은 활성, 누르면 `message` |
| 코드: `message="이메일을 기억하면 다음에 편해요"` | 안내 문구인데 오류(`aria-invalid`)로 읽힘 | 오류일 때만 `message`. 안내는 화면 글자로 |
| 코드: 여러 체크박스로 하나만 고르게 만듦 | 체크박스는 하나만 고르는 규칙을 알리지 못함 | Radio |
| 코드: `<Checkbox className="text-red-500" …>` | 상태별 색이 깨짐 | 색은 바꾸지 않음. `className`은 배치용만 |

## 8. 접근성 요구사항

### 8-1. 필수

| 항목 | 요구사항 | 지금 코드 | 근거 |
|---|---|---|---|
| 이름 | 각 체크박스에 이름 | 네이티브 체크박스를 `<label>`로 감싸 글자가 이름이 됨. `label` 필수, `hideLabel`이어도 유지. 일부만 굵은 글도 하나의 이름으로 읽힘 | WCAG 1.3.1, 4.1.2 |
| 켜짐 상태 | 켜짐 여부를 기계가 알 수 있음 | 네이티브 `checked` | WCAG 4.1.2 |

|---|---|---|---|
