# 아이콘 네이밍 규칙 (제안 v2)

## 1. 규칙 (v2, Material 방식 반영)

### Material은 어떻게 이름 짓나 (저장소 실제 파일명)
| 세트 | 이름 형식 | 실제 예 |
|---|---|---|
| Material Symbols (현행) | `{이름}_{기본값이 아닌 옵션}_{크기}px`, 스타일은 폴더 | `home_24px`, `home_fill1_24px`, `home_grad200fill1_20px` (폴더 `materialsymbolsoutlined`) |
| Material Icons (구버전, Android) | `{스타일}_{이름}_{크기}` | `baseline_home_20`, `baseline_home_24` |

정리하면:
- **크기는 항상 이름 끝에 붙입니다.**
- **기본값과 다른 옵션만 붙입니다**(채움 `fill1`, 두께 `grad200`). 기본값(선, 기본 두께)은 생략합니다.
- **스타일**(outlined, rounded 등)은 접두어나 폴더로 구분합니다.
- **색과 상태는 이름에 넣지 않습니다.**

### 우리 규칙: 세 층으로 나눠 이름을 붙입니다

**① Figma 컴포넌트 세트 이름: `Icon/{분류}/{아이콘 이름}`**
- 예: `Icon/Navigation/Dashboard`
- 아이콘 이름은 영어 PascalCase이고 뜻으로 짓습니다. 반대 뜻은 `Off`(`VisibilityOff`), 오류 조합은 `Error`(`NetworkError`)를 붙입니다.

**② Variant 속성: `Style`, `Size`** (순서 고정)

| 속성 | 값 | 기본값 | 둘 때 |
|---|---|---|---|
| `Style` | `Outline`, `Filled`, `Color` | `Outline` | **모든 아이콘에 둡니다**(인터페이스 통일). `Filled`·`Color` 값은 실제로 그 모양이 있을 때만 |
| `Size` | `16`, `20`, `24`, `32`, `36` | `24` | 시안에서 실제로 쓴 크기만 |

- `Color`는 여러 색이 정해진 아이콘입니다(Status 아이콘 등). 구역 색은 토큰에 고정합니다.
- 그래서 Figma에서 한 Variant의 **전체 이름**은 이렇게 읽힙니다.
  - `Icon/Navigation/Dashboard` · `Style=Outline, Size=24`
  - 문서에서는 줄여서 `Icon/Navigation/Dashboard/Outline/24`로 적습니다.

**③ 내보내기·코드 이름(Key): `{분류}_{이름}[_{스타일}]_{크기}`** (Material Symbols 방식)
- 모두 소문자 snake_case입니다. 단어도 밑줄로 나눕니다(`ContentGroup` → `content_group`).
- **크기는 항상** 붙입니다.
- **스타일은 기본값(`Outline`)이면 생략**하고, `filled`, `color`만 붙입니다.

| Figma | Key |
|---|---|
| `Icon/Navigation/Dashboard` · Outline · 24 | `navigation_dashboard_24` |
| `Icon/Object/GroupFolder` · Filled · 24 | `object_group_folder_filled_24` |
| `Icon/Object/GroupFolder` · Outline · 32 | `object_group_folder_32` |
| `Icon/Status/NetworkError` · Color · 24 | `status_network_error_color_24` |
| `Icon/Action/VisibilityOff` · Outline · 24 | `action_visibility_off_24` |

- Key는 각 Variant의 설명(description)과 SVG 내보내기 파일명(`{Key}.svg`)에 씁니다. AI와 코드는 이 Key로 아이콘을 찾습니다.
- 코드 사용 예: `<Icon name="navigation_dashboard" size={24} />`. 스타일이 있으면 `name="object_group_folder" variant="filled"`처럼 씁니다.

### 이름에 넣지 않는 것
| 요소 | 처리 |
|---|---|
| 색 | 한 가지 색 아이콘은 원본 칠을 `Foreground/Neutral/Secondary`에 연결하고, 쓰는 곳에서 다른 Foreground 토큰으로 바꿉니다. 흰색(`-w`)·검정(`/b`) 두 벌이 하나로 합쳐집니다 |
| 상태 | `-active`, `-deactive`, `Pressed`는 감싼 버튼·컨트롤이 처리합니다. 비활성은 `Foreground/Neutral/Disabled` |

### 크기별 쓰임 (시안 기준)
| Size | 쓰이는 곳 |
|---|---|
| 16 | 작은 보조 표시(미디어 재생·정지, 지우개, 에러 배지) |
| 20 | 버튼, 입력창, 표 안의 작업 아이콘 |
| 24 | 좌측 메뉴, 상단 바, 툴바, 콘텐츠 타입 |
| 32 | 큰 그룹·디스플레이 아이콘 |

**크기 Variant에는 그 크기로 따로 그린 그림만 넣습니다.** 작은 그림을 늘려서 Variant로 만들지 않습니다. 모든 아이콘에 모든 크기를 만들 필요도 없고, 시안에서 쓰는 크기만 둡니다.

### 그리기 규칙 (2026-10-08 정정)
- **아이콘 안의 선 두께, 여백, 위치는 각 아이콘의 고유 값입니다.** 사람 눈으로 시각 보정한 값이라 아이콘마다 소수점까지 다를 수 있고, 그대로 유지합니다. 일괄 기준으로 맞추지 않습니다.
- **이 값들은 토큰이 아닙니다.** 아이콘은 SVG 파일(예: 24×24) 하나로 전달되고, 안쪽 그림은 파일의 일부입니다. 쓰는 쪽(디자이너·개발자)이 정하는 것은 **크기**(`Size/Icon/*`)와 **색**(Foreground 토큰, SVG에서는 `currentColor`) 두 가지뿐입니다. Material Symbols, Lucide도 같은 방식입니다.
- 사용자 `Icon` 프레임에 적힌 선 두께(16→1, 20→1/1.5, 24→1.5/2, 36→2)는 **새 아이콘을 그릴 때 참고하는 기준**입니다. 기존 아이콘을 고치는 규칙이 아닙니다.
- 원본은 **선을 면으로 바꿔(outline stroke) 저장**합니다. 원래 두께 그대로 바꾸기 때문에 겉모습은 같고, 크기를 바꿔도 비율이 유지되며, SVG로 내보낼 때 선 두께가 바뀌는 문제가 없습니다.
- 원본 프레임은 내용을 자르고(clip), 안쪽 도형은 비율 유지(Scale) 제약입니다.
- 원본의 색은 **레이어 칠**에만 토큰을 연결하고 벡터 구역 색은 비웁니다.

### 크기 토큰
원본 Variant의 너비·높이는 Foundation `Size/Icon/*`(XSmall 16, Small 20, Medium 24, Large 32, XLarge 36)에 연결합니다.

### 아이콘으로 보지 않는 것
| 대상 | 처리 |
|---|---|
| 지름이 큰 그림형 아이콘(48·60·75px): `ic-success-60`, `ic_car_*_75`, `ic_emergency_75` 등 | 별도 이름 `Pictogram/{분류}/{이름}`(같은 3층 규칙, Key는 `pictogram_` 접두) ⚑ |
| 아이콘이 들어간 컨트롤: `btn-radio`, `btn-check`, `btn-up-h40`, 지도 `Pin Location`, `Zoom IN` 등 | Button / Icon Button / Selection 컴포넌트로 |
| 지도 위 마우스 커서(`openhand`, `cursor`) | 주석성, 제외 |

## 4. 결정 사항 (2026-10-08)
1. 16px 토큰 추가: `Size/Icon/XSmall` = 16 (Foundation에 등록함)
2. 48·60·75px 그림형 아이콘은 `Pictogram`으로 분리
3. `ic-link` → `Icon/Navigation/Assign` 확정
4. 경고 아이콘 3종은 모양이 달라서 따로 둠: `Warning icon`(48px 노랑 원), `warning triangle`(16px 빨강 채움), `ic-warning-16`(16px 선 ⚠, 배지 "에러" 상태에 쓰임). 지우기 아이콘은 `ic-eraser-16` → `Icon/Action/Erase`
5. 콘텐츠 타입 색 아이콘: **A안**. 컴포넌트가 아니라 Media 아이콘의 `Style=Color` 모양으로 둠
6. `Content Indicator`는 아이콘이 아닌 도형 → 제외

## 5. 정리 방식 (확정: 이 파일에 원본을 둠)
1. `Icon` 프레임의 외부 라이브러리 인스턴스 60개를 분리(detach)합니다.
2. 각각을 이 파일의 로컬 컴포넌트로 만들고, 같은 아이콘의 크기·채움 버전을 하나의 컴포넌트 세트(`Style`, `Size`)로 묶습니다.
3. 새 이름, Key 설명, 색 토큰 연결, 크기 토큰 연결을 적용합니다. 시안에만 있고 프레임에 없던 아이콘(Notifications, Logout, 좌측 메뉴 아이콘 등)도 같은 방식으로 추가합니다.
4. 나중에 시안 화면의 인스턴스를 새 로컬 아이콘으로 바꿔 끼웁니다(swap).

처리 방식(원본은 그대로 두고 복제):
- 로컬 원본은 복제, 외부 원본은 새 인스턴스를 분리, 일반 레이어는 복제해서 컴포넌트로 만듦.
- 단색 아이콘: 칠을 `Foreground/Neutral/Secondary`에 연결. 여러 색 아이콘(`Style=Color`)·픽토그램: 색마다 해당 Semantic 토큰에 연결.
- **불리언 연산은 결과 모양으로 합침**(flatten): 연산 안쪽 재료를 고치면 모양이 달라지기 때문(OTA, Display 24, RepeatOff).
- **여러 색 구역은 색마다 레이어를 나눔**: 컴포넌트 안에서는 구역 색에 연결한 토큰이 저장되지 않기 때문.
- 크기 토큰: 아이콘은 `Size/Icon/*`에 연결. 픽토그램(48·60·75)은 해당 토큰이 없어 연결하지 않음.
- 새 Semantic 토큰: `Foreground/Content/Image`(→`Blue500`), `Foreground/Content/Audio`(→`Orange400`). 원래 색과 같은 값.
- 결정에 따라 색이 바뀐 것: 비디오 아이콘 `#ED4935` → `Red400`(`#F7605F`), 위치 핀 초록 `#31BCA3` → `Green500`(`#009D76`).
